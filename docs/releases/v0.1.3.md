# AgentDeck v0.1.3 native chat test release

这是面向真实 Android + F-Droid Termux 验收的预发布版本，不是正式签名的稳定版。

## 主要变化

- 对话卡片现在进入 App 内原生 Codex transcript，不再把点击主入口直接切换到 Termux。
- 使用官方 `codex app-server` 的 Thread / Turn / Item 协议，支持历史恢复、Markdown、流式回复、停止，以及命令、文件与额外权限审批。
- 新增只监听 `127.0.0.1` 的单客户端 stdio bridge；每次启动使用一次性高熵 token，token 不写入 Room、Preferences 或日志。
- 聊天右上角保留 Termux TUI 入口，用于官方登录、诊断和协议不兼容时兜底。
- 首次使用、工具和设置共享同一环境状态，只显示一个上下文主动作；Ubuntu、Codex 和 bridge 由同一安装链探测、安装、验证。
- Codex 认证会先复用已有登录、`OPENAI_API_KEY`、`CODEX_ACCESS_TOKEN` 或当前 Provider 的 `env_key`；不要求 OpenAI auth 的自定义 Provider 可直接复用。只有配置存在但所需凭据不可用时才会提示操作，不会默认要求重复登录。
- 安装增加进度阶段和原子锁；Codex 下载先使用系统默认 IPv4/IPv6，再回退 IPv4，并按固定长度分段、校验大小与 SHA-256。
- Doctor 会要求将低于 0.147.0 的 CLI 更新到验证版本，兼容的新版本保持不变；app-server 关闭启动升级提示，升级只从 AgentDeck 的可见流程执行。
- 恢复会话时会清理上一次桥断开留下的 `inProgress` turn，避免新消息永远排队；PRoot 作为官方 `externalSandbox` 边界，关闭不兼容的嵌套 sandbox，但继续保留用户审批。
- 每个对话使用私有 bridge lease；Android 覆盖安装或进程回收后再次进入对话，会先精确清理该对话的旧 app-server，避免两个进程同时恢复同一线程。

## 自动化验证

- `./scripts/verify-release.sh` 通过：配方/assets 与 wrapper/assets 完全同步。
- JVM 单测、Debug APK 构建和 Android Lint 通过。
- 使用本机 Codex CLI 0.147.0 完成真实 bridge token 鉴权、`initialize` 和 `thread/list` 冒烟。
- RPC 假服务覆盖 client request/response、通知和 server-initiated approval。

## 安装

- 需要 Android 8.0（API 26）或更高版本。
- `AgentDeck-v0.1.3-debug.apk` 使用测试签名，不要作为生产发布包分发。
- 与 v0.1.0-v0.1.2 使用相同 debug 证书，可直接覆盖安装。

APK SHA-256：

```text
ba8cc0028e0593a00e698249b8a8c4449de0088be34209e7be3f8120478327a3
```

首次启动按“准备 Codex”的主按钮完成 Termux 权限、`allow-external-apps`、Ubuntu、Codex、bridge 和认证检测。缺少认证时可选择 ChatGPT 设备登录或隐藏输入 API Key。环境就绪后，在“对话”点整行进入原生聊天；需要 TUI 时使用右上角终端按钮。

## 已知限制

- Claude Code 仍是不可安装、不可启动的 P1 占位项。
- Profile 当前只做类型约束和本地引用，不会修改 Codex `config.toml`。
- 0.1.3 尚不包含附件、完整 diff、thread 搜索/归档/重命名，以及 MCP elicitation/工具用户输入等扩展 server request。
- 测试 APK 使用 debug 签名；稳定发布仍需要正式签名和完整发布清单。
