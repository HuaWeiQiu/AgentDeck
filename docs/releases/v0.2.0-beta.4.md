# AgentDeck v0.2.0-beta.4 多架构与文件适配预发布

> GitHub Pre-release：ARM64 已完成真机关键路径验收；x86_64 已完成构建与包内容校验，但实际 Runtime 启动门禁尚未完成，不应视为稳定支持。

## 主要变化

- Beta 构建按 `arm64-v8a` 和 `x86_64` 拆分 APK；每个 APK 只携带本架构的 PRoot、loader 和 talloc。Runtime 清单分别固定 Ubuntu Base、Codex 归档名、大小与 SHA-256，marker 禁止跨 ABI 复用。
- 文本/代码、PDF、DOCX、XLSX 通过 App 私有 Runtime 文件适配层生成最多 512 KiB 的纯文本副本。解析限制为 30 秒、20 MiB 原文件、4096 个 ZIP 条目、64 MiB 解压总量、16 MiB 单 XML 和 200 倍压缩比。
- 系统文件选择器多选时，单个文件解析失败不会阻断其余文件；错误显示失败数量和可操作原因。Runtime 私有路径只进入 Codex 协议上下文，不显示在用户对话气泡中。
- PNG/JPEG 继续使用 app-server 原生图片输入。Office 宏、公式、脚本、嵌入对象和附件指令均不会执行；公式只作为文本及缓存值展示。
- RPC 传输结束会立即释放挂起请求；新增断线、畸形 JSON、迟到响应、发送失败、校验失败、断点续传、空间不足和恶意 Office 文件矩阵。
- Runtime 准备页显示 7 个阶段、整体进度、下载容量和长耗时提示；下载状态按时间/容量节流，避免进度 UI 产生高频重组。

## 安装影响

- `versionCode` 为 9，`versionName` 为 `0.2.0-beta.4`，包名和测试签名保持不变，可覆盖当前测试版。
- Runtime 内容版本升级到 `ubuntu-24.04.4-codex-0.147.0-r2`，首次进入需要准备包含 `poppler-utils` 的新 rootfs。Codex home、授权、AgentDeck 配置、项目和对话保存在版本化 rootfs 外，不因本次 Runtime 更新删除。
- 下方 SHA-256 对应本次 GitHub Pre-release 附件；APK 使用测试签名，不是正式生产签名。

## 已知限制

- ARM64 尚需补充：首次空白安装的完整 7 阶段进度、附件真实发送、锁屏/进程回收和长时 soak。
- x86_64 尚需补充：当前 Apple Silicon 主机没有可运行的 x86_64 Android 虚拟设备；API 26 与当前 target API 模拟器安装、Runtime 下载、app-server 启动、发送和 thread resume 尚未执行。因此 x86_64 仍是候选支持，不能据此发布。
- 稳定版仍需要更多 OEM、锁屏/进程回收、低空间、长时 soak 和正式签名覆盖。
