# 计划：消费级完善（beta.9 → 可推荐的 0.2.1）

- 状态：阶段 1–3 已在 V2301A 实测通过；阶段 4 落地一次性本机说明。正式签名 / 去掉 .debug 包名仍待独立发布（会变成新安装）
- 尺子：不是“工程师觉得闭环了”，而是**没听过 Codex / PRoot 的人，愿意留下并再打开第二天**
- 及格线：消费级约 7.5 / 10（当前约 5.5）。本计划只服务把分数做上去
- 通道：日常产品 = Secure；Lab 永远是单独实验包，不进入本计划的完成定义
- 前提：聊天性能第二阶段已随 `v0.2.0-beta.9` 发布，不再当主线

## 产品判断

消费级用户只问四件事：

1. **第一次**：装完要等多久、失败了怎么办、要不要我懂 Linux？
2. **找得到**：人设、模型、会话设置是不是在“编辑会话”里一眼能看见？
3. **丢不掉**：卸了 App、换手机、清数据，我在乎的东西还在不在？
4. **敢不敢信**：这是不是正式 App？密钥会不会被带走？卸载会不会一声不吭清空？

功能清单、Macrobenchmark、第二套 CLI、Host UI Agent，**都不回答这四个问题**。所以它们不在本计划里。

## 最终完成态（用户语言）

一个从没装过 Termux、也不知道什么是 app-server 的人：

1. 装上 **AgentDeck（Secure）**，看到的是在准备聊天环境，不是在装 Linux。
2. 第一次准备失败时，页面告诉他「网络慢，正在换线路」或「空间不够，清出约 1.2 GB」，并有一个主按钮，不必读日志。
3. 十分钟内能发出第一条消息（含首次下载）。连模型时只问「用已有账号还是填密钥」，不出现端口、PATH、exit code。
4. 新建会话就能写「这个助手是谁」——不必先去设置里打开高级选项。
5. 关掉 App、杀进程、第二天再进：对话还在，人设还在，模型还是那个。
6. 设置里有「导出我的会话与角色」。卸装前被提醒导出。导入后名称和人设回来（聊天正文能回来是加分，不是承诺）。
7. 他分得清：日常就用这一个包。没有第二个叫 Lab 的东西出现在这个包里。

做不到第 1、2、4、6 条，就不许叫稳定版。

## 非目标（消费级同样成立）

- 不重写 Codex，不把消息正文双写进 Room。
- 不把 Lab（本地 MCP、无障碍控屏、宿主工具）打进 Secure，也不在 Secure 设置里预告。
- 不做账号云同步、不做多端、不做 Claude 第二套 CLI。
- 不为“看起来完整”打开语音入口或商店页。
- 不把开发者诊断、端口、镜像 URL 原文放到标准模式。

## 消费级完成定义

同时满足才能打 `0.2.1`（对外可以称为测试版里的“日常版”）：

| # | 用户能做到 | 我们怎么验收（内部） |
| --- | --- | --- |
| 1 | 不问任何人，走完首次准备并发出第一条消息 | 冷安装录像：从打开到第一条用户消息，失败也可读 |
| 2 | 新建/编辑会话时直接写人设 | 标准模式（高级选项关闭）UI 中可见角色区 |
| 3 | 知道卸载会丢掉什么，并能先导出 | 卸载前系统或应用内有说明；导出不含密钥 |
| 4 | 导出后再装回来，会话名和人设还在 | 卸装 → 导入 → 卡片上有角色名；新 turn 带人设 |
| 5 | 准备卡住时知道下一步，而不是干等 | 下载页有「换线路中 / 可重试」，无静默 24% |
| 6 | 觉得这是正式产品，不是调试包 | 稳定候选：正式签名 + 正式应用名；商店/发布页只推 Secure |
| 7 | 在第二台普通安卓上也能同样走完 1–5 | 非 Vivo ARM64 冒烟 + x86_64 模拟器主路径 |

内部工程门禁（隔离扫描、JVM、不杀 connected 测试）继续跑，但**过门禁 ≠ 消费级完成**。

## 阶段（按用户痛，不按模块）

版本号仍建议 `beta.10` → `beta.11` → `beta.12` → `0.2.1`，方便发布；对外沟通用下面的名字。

### 1. 第一次就能聊（`beta.10`）

**用户痛**：第一次像在装系统；失败像死机；人设找不到。

做：

- **准备页改成安装向导，不是任务管理器**  
  标题用「正在准备聊天环境」。副文案只保留：还要多久的粗估、要不要连 Wi-Fi、空间不够怎么办。  
  「阶段 2/7 · 16%」可留在高级/开发者，标准模式改成「下载组件 28 / 116 MB」+「网络较慢，正在换线路」。
- **VPN / 选源用白话**  
  判定到境外出口时： 「当前网络走了国际线路，下载可能较慢，正在尝试国内线路」。不出现 Cloudflare、loc=、IP。
- **角色放到创建会话的主路径**  
  新建会话：名称 +「这个助手是谁」（可选，可跳过）+ 开始聊。  
  编辑会话：角色开关永远可见；打开后才展开五字段。  
  高级选项继续只藏：多 Agent、权限细则、TOML、扩展底层。
- **空状态**  
  一个会话都没有时：一句话 + 一个按钮「新建会话」，不要空白列表。  
  还没连模型：会话列表仍在，点进去先引导连接，不要甩内部错误。
- **排版中**  
  「正在排版回复」超过数秒仍无内容时，显示「回复已收到，正在整理显示」，禁止永久转圈（已有竞态修复，这里补文案与超时）。

不做：不解释镜像域名；不把诊断入口放到标准设置首页。

验收（消费级）：找一个没参与开发的人，高级选项默认关，让他独立完成「装上 → 等到能聊 → 给助手起一个人设 → 发一句」。过程中不问“高级在哪”，才算过。

### 2. 丢掉也不至于归零（`beta.11`）

**用户痛**：卸一次 App，人设和会话卡片没了，而且没人提前说。

做：

- **设置 →「备份与恢复」（标准模式就有）**  
  导出一个用户能在文件管理器里看见的文件（工作区或系统分享）。  
  里面只有：会话名称、人设五字段、选过的扩展 ID、模型绑定的**非密钥**信息。  
  里面绝不能有：API Key、MCP Bearer、capability、聊天正文、附件。
- **卸载与清数据之前要说实话**  
  设置里写清楚：  
  - 卸装 / 清数据会删除本机聊天环境和会话列表  
  - 聊天原文存在本机运行环境里，不是云端  
  - 请先导出「会话与角色」  
  做不到系统级卸载拦截就在设置置顶，并在每次导出成功后记住时间。
- **导入**  
  选文件 → 预览将恢复几条会话、几个人设 → 确认。  
  密钥类只显示「该模型服务需要重新验证」，引导去「模型连接」，绝不写回明文。  
  导入后新对话必须带上人设（走现有 `developer_instructions`）。
- **可选**：Android 自动备份只备份上述元数据文件，不备份整份 Runtime。默认关闭或需用户同意，避免把意外状态同步到新机还以为聊天也回来了。

验收：卸装重装后，不靠开发者 adb，用户用备份文件恢复「会话名 + 人设」。正文在不在都不许写成“聊天已云备份”。

### 3. 换一台手机也成立（`beta.12`）

**用户痛**：只在你那台 Vivo 上好用，不等于产品好用。

做（对外仍是同一套界面，对内补证据）：

- 再找一台**非 Funtouch** 的普通安卓，让非开发者走阶段 1 的独立任务。
- x86_64 模拟器走通同一条用户路径（装 → 准备 → 连模型可用假/已有配置 → 发一条 → 再进）。失败停在人话阶段名。
- 连续使用：同一会话用半小时或聊很多轮，过程中锁屏、切走再回来，不能丢当前回复、不能再进就要重装环境。
- 文案过一遍：所有标准模式错误只有「发生了什么 + 我能按的那个按钮」。开发者细节进「导出诊断」（仍在开发者模式）。

验收：第二台真机独立任务通过；没有“只有开发者那台行”。缺第二台真机就不能宣称消费级完成。

### 4. 看起来像正式产品（`0.2.1`）

**用户痛**：包名带 debug、测试签名、GitHub 预发布页同时丢 Secure 和 Lab，不像能给人的 App。

做：

- 日常安装包：正式签名、应用名「AgentDeck」、`applicationId` 去掉 `.debug`。  
  现有测试安装继续用 beta/测试签名覆盖，避免开发机被拆；**对外链接只给正式包**。
- 发布页 / 说明只主推一个包（Secure）。Lab 单独一页，标题写「实验版，不要当日常使用」。
- 首次打开有极短的「聊天记录只存在这台手机」说明，可跳过，不做成教程关卡。
- 关于页：版本号、隐私要点（密钥不离开本机、无聊天云同步）、备份入口。

验收：把正式包发给非技术用户，他能说出让人设和备份在哪，且不知道 Lab 的存在。

## 明确不在本计划（避免分数假涨）

| 想做的事 | 为什么现在不做 | 以后放哪 |
| --- | --- | --- |
| Lab UI Agent | 消费级用户不应看到控屏/无障碍；会拖垮主路径 | `0.2.1` 后独立 Lab 预发布 |
| 本地 MCP 真机 | 不是日常包能力 | 同上 |
| 语音输入、商店 | 主叙事还不是「语音助手/插件市场」 | 消费级 7.5 之后再评估 |
| Claude / 第二 CLI | 一条 CLI 的安装失败都还不够白话 | 有升级/失败手册之后 |
| 云同步聊天 | 与「正文只信本机 rollout」冲突，且变成另一款产品 | 除非单独立项 |

## 工程护栏（用户看不见，但必须守）

- 一个阶段一个预发布，禁止把「向导 + 备份 + 换包名」塞进一次大改。
- 备份 schema 变更必须有测试；导入失败要可重试，不能写坏现有会话。
- 标准模式禁止出现端口、PATH、exit code、镜像域名。
- Secure 扫描门禁保持：Lab 代码进不了日常包。
- 禁止 kill `connectedAndroidTest`（会卸包删用户数据）。这是消费级事故，不是开发者逸事。
- 官方性能数字继续只用 Secure 真机 gfxinfo，不写进用户面向的商店要点。

## 顺序与取舍

只按对消费级分数的贡献排序：

| 顺序 | 阶段 | 主要拉分项 | 体量 |
| --- | --- | --- | --- |
| 先做 | 第一次就能聊 | 首次体验 4→7，好懂 5→7 | 小 |
| 紧接着 | 丢掉也不至于归零 | 敢留下 4.5→7，稳定 5→6.5 | 中 |
| 然后 | 换一台也成立 | 稳定/完整，去掉“样品机幻觉” | 中，卡设备 |
| 最后 | 看起来像正式产品 | 信任 6→8 | 小，卡签名 |

**若只能做一周：做阶段 1 的角色主路径 + 准备页白话，以及阶段 2 的导出。**  
没有这两项，后面签名和多设备都只是把难用的东西包装得更像正式版。

## 和旧方案的差别

旧方案按工程模块切（入口、诊断、矩阵、签名）。本方案按**消费者会不会留下**切。诊断包、HANDOFF 收口、事故手册仍要做，但降为阶段 1/3 的内部工作，不再当成给用户的交付物。
