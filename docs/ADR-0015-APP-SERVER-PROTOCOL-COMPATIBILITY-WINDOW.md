# ADR-0015：上游 app-server 协议版本兼容窗口

- 状态：Accepted
- 日期：2026-08-22
- 相关：ADR-0009、ADR-0010、ADR-0013、ADR-0014

## 背景

AgentDeck 锁定 Codex CLI 0.147.0 的 app-server WebSocket 协议（线程管理、turn、审批、MCP 状态等 RPC）。上游 Codex 持续演进，RPC 方法、参数与事件可能在不通知下游的情况下变更或移除。AgentDeck 既不能盲目跟随每次上游发版，也不能无限期钉死一个版本而错过安全与功能修复。

## 决策

1. manifest 钉死 Codex CLI 精确版本（当前 0.147.0）及其 SHA-256。App 不做"latest"语义；升级 Codex 版本是一次显式的、经过验证的 manifest 变更。
2. 仓库维护一份"已验证协议能力集"记录：App 实际依赖的 RPC 方法、参数字段、事件类型与审批/MCP 行为，与 stability matrix 的 RPC 场景一一对应。
3. 升级 Codex 版本的发布门禁：stability matrix 中所有 RPC 场景对新版本全绿后才允许进入发布通道；任一场景失败则该版本不得写入生产 manifest。门禁结果与版本号一并归档。
4. App 对未知 RPC 方法与未知字段必须容忍（向前兼容）：解析时忽略未知字段，收到未知方法或未知事件时记录日志并丢弃，不得使会话崩溃。
5. App 对缺失的已知方法降级处理并提示：当新版本 Codex 移除或改名了已验证能力集中的方法时，对应功能进入降级态（禁用入口、说明原因），不得静默失败。
6. "最低支持协议版本"的判定方式：以 RPC 层 JVM 测试覆盖的场景为契约。JVM 测试使用录制的真实 app-server 报文回放，覆盖场景即契约；某版本 Codex 能通过全部契约场景即视为兼容，无需逐字段比对上游文档。

## 验证

- JVM：契约场景回放测试全部通过；未知方法/字段容忍性测试；缺失已知方法的降级提示测试。
- 发布门禁：候选 Codex 版本在 stability matrix RPC 场景（对话、审批、会话恢复、MCP 状态、扩展）全绿。
- 真机：升级 manifest 后 ARM64 真机完成一次真实对话与会话恢复验收。

## 后果

- Codex 升级节奏由 AgentDeck 掌控，上游 breaking change 不会直接击穿生产。
- 契约场景的 JVM 测试成为长期维护成本；新增依赖的 RPC 能力必须同步补测试，否则不受向前兼容保护。
- 未知字段容忍策略使 App 在上游加字段时无需发版；移除方法时依赖降级提示兜底，用户体验有明确下界。
