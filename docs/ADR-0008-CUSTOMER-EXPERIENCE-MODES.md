# ADR-0008：标准、高级与开发者三级体验

- 状态：已接受
- 日期：2026-08-09

## 背景

AgentDeck 已经能检测 Termux、Ubuntu、Codex、认证和聊天桥，但这些实现细节直接出现在主导航、首次设置、聊天工具栏和错误消息中。普通用户必须理解运行时、权限和命令才能开始对话，且技术日志、危险操作和日常设置没有明确边界。

移动端同类项目的共同经验是：会话和需要用户处理的决定属于主表面；安装器、终端、协议事件和诊断只在需要时出现。简化界面不能隐藏危险操作的真实影响，也不能用假进度或笼统成功替代可验证状态。

## 决策

1. AgentDeck 提供三个逐级开放的体验层级：
   - `STANDARD`：默认。只展示对话、必要的模型连接、客户可理解的运行状态和知情授权。
   - `ADVANCED`：由设置页显式开启。展示自定义 Provider、Endpoint、模型 ID、工作区、权限策略、代理和 Runtime 管理。
   - `DEVELOPER`：通过“关于”页连续点击版本号开启。展示脱敏日志、协议事件、进程、Runtime 版本、诊断操作和 Feature Flags。
2. 层级只控制呈现和可发现性，不改变安全边界。开发者模式也不得绕过 Keystore、审批、路径校验或日志脱敏。
3. 标准模式不出现 Termux、PRoot、Ubuntu、app-server、WebSocket、PID、端口、PATH、退出码和 recipe ID。内部错误统一映射为有限的客户状态和一个主动作：准备、可用、需要操作、自动修复、暂时不可用。
4. 默认底部导航只有“对话”和“设置”。安装与修复是首次流程或设置中的上下文页面，不占用长期主导航。
5. 标准模式自动检测现有 Codex 登录、配置文件和受管 Provider。只有确实缺少可用认证时才要求“连接模型服务”，不得默认重复登录。
6. 标准对话只直接显示用户消息、Agent 最终回复、简洁活动摘要和必须处理的审批/提问。思考和工具详情默认折叠；原始协议、完整命令输出和诊断信息只在高级或开发者表面出现。
7. 审批必须使用客户可理解的目的和影响描述，并保留“查看技术详情”。默认主操作采用最小权限；命令、工作目录和服务端声明的可选决定不得被 UI 猜测或改写。
8. 安装和修复必须有真实阶段、可恢复状态和明确失败原因。无法获得可信字节进度时只显示阶段，不伪造百分比。
9. 所有开发者日志有界保存并默认脱敏 API Key、capability token、认证文件内容和用户消息；诊断包只能由用户主动导出。

## 客户流程

```text
首次打开
  -> 自动检查设备与已有配置
  -> 必要时下载并准备本机运行环境
  -> 自动复用已有认证，或引导连接模型服务
  -> 开始对话

日常打开
  -> 对话列表
  -> 进入同一 thread
  -> 发送、停止、审批或回答 Agent 问题
```

客户错误示例：

```text
运行环境需要修复
部分运行组件未正确安装。修复不会删除对话和项目文件。

[自动修复]
```

技术原因仍保存在内部诊断对象中，但标准模式不直接显示 `exit 127`、连接端口或内部包名。

## 后果

- Compose 页面消费客户状态和展示策略，不直接渲染底层 Doctor/协议文本。
- 当前“工具”Tab、常驻终端按钮、技术型卡片编辑字段和原始错误需要迁移到高级或上下文页面。
- 自动修复、后台恢复和审批文案成为发布验收项，不能只以单元测试覆盖。
- 高级与开发者入口保持完整控制力，但不增加默认客户的认知负担。
